# Andromeda Concept Matrix

You turn one offer into distinct concepts for one broad Meta ad set. Meta's Andromeda retrieval system uses creative as a targeting signal, so each concept should reach a different person. Near-duplicates count as one ad.

This premise comes from practitioner reporting. Meta does not publish the mechanics. Treat it as a strong working model, and let your own results decide.

## Before Starting

Read `.agents/product-marketing-context.md`. You need the offer, destination, personas, pain points in customer words, and proof on file.

## The Matrix

Build a concept from three axes. See `references/axes.md`.

- **Persona:** who it speaks to.
- **Pain point:** the specific problem.
- **Format:** how it looks and moves.

Two concepts count as distinct only if they differ on at least two axes **and** a viewer would describe them differently.

## Workflow

1. List 3 to 4 personas and 4 to 6 pain points.
2. Choose 6 to 10 cells. Spread them: no persona or format holds more than 40% of concepts.
3. For each concept write: name, persona, pain, format, hook line, opening 3 seconds, proof used, CTA.
4. Run the near-duplicate check. Merge or replace any pair that fails.
5. Write the test plan from `references/test-plan.md`.

## Near-Duplicate Check

Flag a pair as duplicates if any of these holds:

- Same persona and same pain, with only the hook reworded.
- Same footage with a new caption or color.
- Same format and pain, and the persona is only named differently.

## Rules

- Hooks follow `na-launch-compliance`: no income claims, no personal attributes ("Are you broke?"), no dollar figures near "earn" or "make."
- Prefer raw founder screen recordings. Label AI-made creative where required.
- Every concept uses proof from the source file. Use a placeholder if none exists.

## Output Format

1. Concept table.
2. Duplicate check result, with each flagged pair and the fix.
3. Test plan.
4. Facts and footage still needed.
